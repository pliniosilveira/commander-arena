# Feather deck, group 2 (damage, modes, activation limits, commander statics): provisional decisions D-1310 to D-1316

Issue 27, branch `support-feather`. Cards: Bastion Protector, Fall of the Hammer, Reckless Rage, Giggling Skitterspike, Light the Way, Hall of Oracles. All six read as supported with no override. The lead folds these entries into `docs/DECISIONS.md` with the next free numbers (the code and the tests say D-1310 to D-1316; the numbers in the code comments are the provisional ones).

The Comprehensive Rules were read with `pnpm rule` from the owner's copy (`/workspace/commander-arena-rules/comprehensive-rules.txt`). Scryfall rulings were not fetched (blocked in a cloud session); none is relied on. The version constants (`ENGINE_VERSION`, `PARSER_VERSION`) and the golden snapshot were not touched: this group changes the state shape (`TurnLog.castSpells`, `GameObject.monstrous`), the events (`becameMonstrous`) and six cards from unsupported to supported, so the lead bumps both and regenerates the snapshot and the derive digests.

## D-1310: "Commander" is a legal filter of a static ability's subject (CR 903.3)

- Context: Bastion Protector has "Commander creatures you control get +2/+2 and have indestructible." The engine's `ObjectFilter.commander` (D-145, D-149) was refused in a static ability's subject by `validateCard` (`readsCombatOrSource` counted it with `attacking` and the other things `derive` cannot read while it settles the layers), and the filter test read `FilterSubject.commander`, a value only the callers of `select.ts` provide.
- Decision: a commander is a card its owner designated (CR 903.3), a fact no layer changes (it is `GameState.cards[card].isCommander`, a token or a copy is not one), so `derive` can read it. `matchesFilterWith` reads `FilterSubject.commander` when the caller gives it and the object itself when it does not (`isCommanderObject`, `rules/melded.ts`: a melded permanent counts, CR 903.3b). `checkStaticSubject` uses `readsCombatOrSourceBesidesCommander`, so a static subject may name commanders; a count in a static ability (`colorsAmong`, `countOf`) still refuses it, as before. The parser reads "commander" as a word before a type, in the permanent phrases only (`COMMANDER_MODIFIER` of `permanentPhrase`: "commander creatures you control", "other commander creatures you control", "commander creatures"), never in the spell, card, cost or condition phrases that share `MODIFIER`. The rule `noun.target-commander` ("target commander") is untouched and still takes "target commander creature" first, which therefore stays unread.
- Alternatives: adding `commander` to the `FilterSubject` that `derive-statics.ts` builds for every permanent (an extra lookup in the hot path for the one ability that needs it); a new `StaticSubject` kind `commanders` (a second way to say what a filter already says).
- Consequences: any static ability about commanders reads ("Commander creatures you control have ward {1}", "Other commander creatures you control get +1/+1"). The engine proof is an indestructible commander that survives lethal damage and a destroy effect only while the Guard is on the battlefield, and not a commander of the opponent or a creature that is no commander. The web words it with the older filter words: "Creature commanders you control get +2/+2."

## D-1311: Spells cast this turn by card type: `spellsCastThisTurn.ofTypes`, `TurnLog.castSpells`; "Activate only as a sorcery and only if ..." (CR 602.5b, 602.5d, 601.2i, 707.10)

- Context: Hall of Oracles has "{T}: Put a +1/+1 counter on target creature. Activate only as a sorcery and only if you've cast an instant or sorcery spell this turn." The engine had the condition `spellsCastThisTurn` (D-318: three or more spells) as a per-seat count with no memory of the kinds, and the grammar read the restrictions only in the order "only if ... and only as a sorcery".
- Decision: `TurnLog` gets `castSpells`, one entry for each spell cast this turn (`finishCast` in `cast.ts`: the seat and the card types the spell was cast with, as `derive` gives them for the object on the stack; a copy is not cast, CR 707.10, so it adds none; the log empties as the next turn begins like the rest of it). The condition `spellsCastThisTurn` gets an optional `ofTypes`: with it, only the spells of the seat that have at least one of those types count; without it the old count of the seat is read, unchanged. `validateCard` refuses an empty or non-type `ofTypes`. Parser: `condition.spells-cast-this-turn` also reads "you've cast an instant or sorcery spell this turn" (one spell, `a`/`an` agreeing with the first type, one type or types joined by "or"), and a new rule `restriction.sorcery-and-if` reads "Activate only as a sorcery and only if <condition>." into one restriction with both parts (the other order is `restriction.if`).
- Alternatives: counting instants and sorceries in a second per-seat number (one more field for each kind someone asks about); reading the stack object's types when the ability is activated (the spell may be gone).
- Consequences: "if you've cast a creature spell this turn", "an artifact spell" and the like read for activations and, where a card uses it, for any condition that reads `spellsCastThisTurn`. Not read: a count with a kind ("two or more creature spells"), a color or a subtype, "noncreature", an opponent's spells. The state shape changes (`ENGINE_VERSION`). Web: the condition is worded ("you have cast an instant or sorcery spell this turn") and the chooser label of the Hall says "(sorcery speed). Activate only if ...".

## D-1312: Monstrosity: the effect `monstrosity` and the designation `monstrous` (CR 701.37)

- Context: Giggling Skitterspike has "{5}: Monstrosity 5." The engine had no monstrous designation and no such action.
- Decision: `GameObject.monstrous?: true` is the designation (CR 701.37b: no rules meaning of its own, not an ability, not a copiable value; a permanent that leaves the battlefield is a new object, CR 400.7, so it is not monstrous when it comes back). The effect `{ kind: 'monstrosity'; count: Amount }` is the keyword action (CR 701.37a): for the permanent the ability belongs to, if it is still on the battlefield and not monstrous, put `count` +1/+1 counters on it (as `addCounters` does, with the rule that a permanent that can't have the counters gets none, D-380) and make it monstrous; a permanent that is monstrous already, or has left, does nothing, so two activations on the stack together give the counters once. A permanent that can't have the counters still becomes monstrous. The event `becameMonstrous` comes after the `counterAdded` event. `validateCard` allows it only in an ability of a permanent and a count of one or more. The view shows `monstrous` for a permanent on the battlefield. Parser: `effect.monstrosity` ("Monstrosity 5", a whole number of one or more) and its lowering `lower.monstrosity`; "Monstrosity X" (CR 701.37c: X as the permanent became monstrous, read by other abilities) is not read. Web: the label "Monstrosity 5" and the log line "X became monstrous."
- Alternatives: lowering it to a conditional of two effects (`addCounters` and a "become monstrous" effect) with a condition "is not monstrous" (three new nodes for one keyword action, and a monstrosity that raced with itself on the stack would have to be argued).
- Consequences: every "Monstrosity N" with a number reads. Not built, and in `docs/ROADMAP.md`: the trigger "When ~ becomes monstrous" (the event is there), the condition and filter "if ~ is monstrous", "monstrous creatures", "Monstrosity X". The state shape and the events change (`ENGINE_VERSION`).

## D-1313: A bite at "another target creature" and the second damage of "~ deals 4 damage to X and 2 damage to Y" (CR 115.3, 120.3, 608.2b)

- Context: Fall of the Hammer ("Target creature you control deals damage equal to its power to another target creature.") was recognised by `effect.bite` and refused in the lowering: the noun "another target creature" carries `other: true` (not the source of the ability), which the bite's lowering could only turn into "each other creature". Reckless Rage ("~ deals 4 damage to target creature you don't control and 2 damage to target creature you control.") stopped at the second amount: no rule read a damage instruction without a subject.
- Decision: in `lower.damage`, when the source of the damage is a target (a bite) and the recipient is one noun "another target ..." (a list of two is not read), the noun is lowered with `otherTarget`: a target slot whose `differentFrom` is the slot before it, the target of the creature that deals the damage (CR 115.3: the same object can't be chosen for both; the engine's `TargetSpec.differentFrom`, D-151). A recipient "another target ..." for the creature of a trigger ("it deals damage to another target creature") stays unread: "another" there would mean "not the creature that entered", which is not said. A new rule `effect.damage-same-source` reads "2 damage to target creature you control" (a number or X, "damage to" and the damage recipients, no subject) as a `dealDamage` clause flagged `sameSource`, which the lowering of a sentence accepts only right after a damage clause of the same sentence that names no other source and is joined by "and" (`sameSourceHolds`, D-152); anywhere else it is refused. The two damages are two `dealDamage` effects of a sequence (CR 608.2c).
- Alternatives: lowering "another target" as the engine's `other: true` filter (not the source of the spell: nothing) and checking the two targets at resolution (a legal cast the rules forbid).
- Consequences: every bite with a second different target, and every "~ deals N damage to A and M damage to B", read. An engine proof: the two targets must differ, a creature that is gone as the spell resolves deals no damage, a damaged target that is gone takes none and the creature takes none back (CR 608.2b).

## D-1314: "target creature or Vehicle": a card type and a subtype in a choice (CR 205.2a, 205.3g)

- Context: Light the Way has "Put a +1/+1 counter on target creature or Vehicle." The permanent phrases read a choice of card types ("artifact or enchantment") and a choice of subtypes ("Angel or Cleric") but not one of each.
- Decision: `permanentPhrase` reads one card type and one subtype joined by " or ", in either order, with the control suffix after the pair: the filter is an `anyOf` of `{ types: [t] }` and `{ subtypes: [s] }`. A word of the subtype table in the singular, the same subtypes as the older subtype choice (`SubtypeMode`). A Vehicle is an artifact that is a creature only while crewed (CR 301.7), so "creature or Vehicle" means both.
- Alternatives: a new filter field "Vehicle" (`anyOf` already says it).
- Consequences: "target creature or Elf", "target artifact or Equipment", "target Vehicle or creature you don't control" read. A choice of three words ("creature, Vehicle, or Elf"; "creature or Dragon or Elf") is still not read. Two corpus tests that named "creature or Dragon" as an unread line moved to "creature or Dragon or Elf" (still unread): the diagnostics test of `convert-grammar-rules.test.ts` and the rejects of `effect.add-counters`.

## D-1315: Events joined by commas ("attacks, blocks, or becomes the target of a spell"), and "it" after "becomes the target" (CR 603.2c, 603.2)

- Context: Giggling Skitterspike has "Whenever this creature attacks, blocks, or becomes the target of a spell, it deals damage equal to its power to each opponent." The segmenter ended the trigger at the first comma, `trigger.or` read only events joined by "or", and the binding pass refused "it" in the body of a "becomes the target" trigger (it could not tell the permanent from the spell).
- Decision: `segment.ts` keeps a comma inside the trigger when an event ends right before it and an event follows it (`insideEventList`: "enters", "dies", "attacks", "blocks", "becomes tapped/untapped/blocked/the target of a spell"); the comma that ends the list is followed by the effect and still ends the trigger. `trigger.or` reads "A or B [or C]" as before and the list of a comma, "A, B, or C" (the Oxford comma, three or more events, no repeated event); each event is an ability of its own (CR 603.2c). In the binding pass `becomesTarget` is an event after which `~` is still the object "it" means (`SELF_EVENTS`): the spell is "that spell", never "it".
- Alternatives: reading "it" in a `becomesTarget` body as the trigger subject only when the effect says so (more code for the same cases).
- Consequences: "Whenever ~ enters, attacks, or dies, ..." and every list of events of one subject read. A trigger "Whenever ~ becomes the target of a spell or ability, it ..." now binds "it" to `~`; the golden corpus shows no other card changed. Not read: "or ability" in the list, "A, B or C" without the comma, two events of different subjects.
