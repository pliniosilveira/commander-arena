# Feather deck, group 1 (small spell effects): provisional decisions D-1300 to D-1308

Issue 27, branch `support-feather`. Cards: Crimson Wisps, Gods Willing, Shelter, Might of the Meek, Legion Leadership // Legion Stronghold, Fleeting Flight, Fists of Flame. All seven read as supported with no override. The lead folds these entries into `docs/DECISIONS.md` with the next free numbers (the code and the tests say D-1300 to D-1308; the numbers in the code comments are the provisional ones). The Comprehensive Rules were read with `pnpm rule` from the copy of the owner's private rules repository (`COMMANDER_ARENA_CR_FILE`); the rule numbers cited were looked up there. Scryfall rulings were not fetched (blocked in a cloud session); none is relied on.

## D-1300: "For each card you've drawn this turn": the amount `cardsDrawnThisTurn` (CR 121.1, 608.2h)

- Context: Fists of Flame says "Draw a card. Until end of turn, target creature gains trample and gets +1/+0 for each card you've drawn this turn." The engine keeps `SeatState.cardsDrawnThisTurn` (the count the "nth card each turn" trigger reads, D-111) but no amount read it.
- Decision: a new `Amount` `{ kind: 'cardsDrawnThisTurn' }`: the cards the controller of the spell or ability has drawn so far this turn, counted as the instruction runs (CR 608.2h: "determined only once, when the effect is applied"), so the card an earlier instruction of the same resolution drew counts, and so does the draw of the draw step. A draw replaced by the commander going to the command zone (CR 903.9b) is not a card drawn and the existing counter already leaves it out. It is a `StateAmount` (`rules/amounts.ts` `stateAmountOf`), valid anywhere an amount of an effect is, and refused in a static ability's power and toughness (`checkCountOnly`: nothing would refresh a layer when a card is drawn, CR 613.8). Parser: `amount.for-each-card-drawn` ("for each card you've drawn this turn", "you have drawn"; `rules/amount/feather-g1.ts`), listed in `FOR_EACH_AMOUNTS`, lowered by `lower/amounts.ts` (`amount:cardsDrawnThisTurn`); and the lead sentence `effect.lead-gain` ("Until end of turn, target creature gains trample and gets +1/+0 for each card you've drawn this turn") now takes the count after a pump that ends the sentence (not an X, as `PUMP_TAIL` refuses it). Web: `amount-text.ts` ("the number of cards you've drawn this turn").
- Alternatives: a `thisWay` count of the cards the spell itself drew (wrong: the text counts every card drawn this turn, the draw step included); a new `SeatState` field (the existing counter is the one source of truth).
- Consequences: the opponent's draws and a game-long count are not read ("for each card an opponent has drawn this turn" and "this game" are rejects of the rule). The count is of the controller only.

## D-1301: "gains protection from the color of your choice": `Keyword` quality `colorOfChoice`, the instruction `protectionColor` and the decision purpose `protectionColor` (CR 702.16, 608.2d)

- Context: Gods Willing and Shelter say "Target creature you control gains protection from the color of your choice until end of turn." The engine had protection from a color or a card type (D-229, D-259, D-376, D-377) only on a printed keyword or a static grant, and one color choice, made as a permanent enters (D-100). Nothing asked for a color as an effect resolves, and an effect could grant no protection at all (`GRANTABLE_KEYWORDS` excludes it).
- Decision: a `grantKeyword` effect may carry `{ kind: 'protection', from: 'colorOfChoice' }`. As it runs (`rules/effects.ts`) it queues the instruction `{ kind: 'protectionColor', effect, chosen: null }` (`rules/protection-choice.ts`), which asks the controller of the spell or ability a `chooseOption` decision of the new purpose `protectionColor` (`options` W, U, B, R, G; `protects`: the permanents the grant would affect, as they are now), with nothing asked when none is left on the battlefield (a target that is gone, CR 608.2b). The answer (`answerResolutionProtectionColor`, called from `api.ts`; the event `optionChosen` of that purpose) is written on the instruction, and the grant then runs as `{ protection, from: 'color', colors: [chosen] }` with the same objects and duration, so targeting, damage, blocking and attaching read it where they read every protection (`rules/protection.ts`, unchanged). The color is chosen as the spell resolves (CR 608.2d), never as it is cast, so nobody can respond knowing it. A group ("creatures you control gain protection ...", one choice for all, a `each` selector) works the same. `validateCard` accepts `colorOfChoice` only in a `grantKeyword` effect (a printed keyword and a static grant refuse it with a clear message). Two instances with different colors are two protections (CR 702.16g) and the same color twice is redundant (CR 702.16m): the layer 6 comparison of D-376 already keeps protections as written.
- Alternatives: a `chooseOne` of five `grantKeyword` options (no engine change, but the question would be a list of five effect labels, the AI could not tell them from other instructions, and no `protects` list could be shown); a color stored in `ResolutionContext` and a keyword that reads it (two nodes and new state where one instruction does the job); the purpose `color` of "as this enters" (the UI and the agents answer that one from the permanent's own point of view).
- Consequences: any "gains protection from the color of your choice" of a spell or ability, for one object or a group, needs only a grammar rule. The AI answers with the color that threatens the creature (D-1303). Limits (`docs/ROADMAP.md`): the view tells only that a creature has protection, not from what; the log line names the color chosen.

## D-1302: An effect gives protection from named colors or card types; the parser rule `effect.gain-protection` (CR 702.16, 613.1f)

- Context: "Target creature gains protection from red until end of turn" was a backlog line (7 cards): `effect.gain-keyword` rejected it and the engine's `validateCard` refused `protection` in a `grantKeyword` effect.
- Decision: `validateCard` accepts `{ protection, from: 'color', colors }` and `{ protection, from: 'cardType', types }` in a `grantKeyword` effect (colors and types checked as for a static grant); `chosenCardType` and `colorsNotInCommanderIdentity` stay static-only (they read a permanent's choice or a commander). The parser rule `effect.gain-protection` reads one object ("target creature", "~", "it", "that creature", the permanent an Aura or Equipment is attached to) that gains protection from "the color of your choice" or from named colors ("red and from blue": two protections, CR 702.16g) until end of turn, lowered by `lower/continuous.ts` (`GRANT_KEYWORD`; `IrKeywordArg.protection`; needs `keyword:protection`). It is quiet (`quietly`), so a line it does not read stops where it always did. Not read: a group, a card type in an effect (the engine accepts it, no card needs the words yet), another duration, protection together with other keywords in one gain.
- Consequences: two corpus tests that named "gains protection from red" as unread moved to "gains protection from artifacts" (`convert-grammar-corpus-p5.test.ts`, `parser-p5.test.ts`).

## D-1303: The casual agent: which color, and which spells help their target (CR 702.16b)

- Context: the new question needs an answer from `CasualAgent` (the compiler enforces the decision switch only for kinds, not purposes), and its text-reading `helpsItsTarget` decides on whom a spell with a creature target goes: the opponent's creature unless the text reads as a help.
- Decision: `casual-protection.ts` answers the color question: 100 points for each color of a spell or ability of an opponent on the stack that targets one of the creatures named in `protects` (the Bolt the protection was cast against), then 3 points for each opposing creature of the color and 1 for each other permanent (the battlefield is public); the most points wins, ties to the first option. `casual-helpful.ts` reads "gains protection from" as a help, and two wordings that carry a word of its "hurts" list as no harm: "Prevent all combat damage that would be dealt to it" (Fleeting Flight) and "becomes [color] and gains haste" (Crimson Wisps). `HeuristicAgent` uses the casual answer; `RandomLegalAgent` picks an option.
- Alternatives: leave the new spells reading as hostile (Gods Willing could only target its controller's creatures, but Fleeting Flight, Crimson Wisps and the pumps would go on the opponent's best creature).

## D-1304: "becomes red and gains haste until end of turn" (CR 613.1e, 613.1f)

- Decision: `effect.becomes` reads, after a color alone, " and gains [keywords]" with the same duration: a `setColors` and a `grantKeyword` for each keyword, on the same object. The creature types and card types of the same rule (and "a Frog and gains ...") are still read only by `effect.lead-becomes` and `effect.lead-becomes-target` in the words they have; the rule drops them whole (reject lines).
- Consequences: Crimson Wisps. The engine already ran both effects; the color of the creature is read by any protection and color-dependent rule while the effect lasts.

## D-1305: "Prevent all combat damage that would be dealt to it this turn" (CR 615, 609.7a)

- Decision: `effect.prevent-all` takes `noun.it` as a recipient (a shield on the creature an earlier sentence of the spell named, "Put a +1/+1 counter on target creature. It gains flying ... Prevent all combat damage that would be dealt to it this turn."). The engine's `preventDamage` of an object selector was run before (D-145 to D-147); only the words were missing. "it" with nothing before it is dropped (the binding pass refuses an anaphor with no antecedent).

## D-1306: "It also gets +1/+0 until end of turn if you control a Mouse." (CR 608.2c)

- Decision: `effect.pump` reads "also" before "gets" (as `effect.gain-keyword` reads it for "gains", D-176): in addition to what the sentence before gave the same creature. The trailing "if you control a Mouse" was already read as the condition of the clause (`conditional`), checked as the spell resolves, so a Mouse the controller controls at that moment counts (the Mouse can be the target itself) and an opponent's Mouse does not.

## D-1307: "Until end of turn, double target creature's power and it gains first strike." (CR 701.10)

- Decision: the lead rule `effect.lead-double-pt` (`rules/effect/feather-g1.ts`): the duration, the doubling of the power, toughness or both of one target in the possessive, and optionally " and it gains [keywords]": the engine's `modifyPt` with the `affected` amounts (D-145: +X/+0 where X is the creature's power as the spell resolves, CR 701.10b) and a `grantKeyword` for each keyword, both on the same target (one chosen target, CR 115.1; "it" is the creature the doubling names). Only a target (not "~'s" or a group). Quiet.
