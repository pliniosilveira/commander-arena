# Danitha deck, group 6: provisional decisions (D-1260 to D-1262)

Cards: Kutzil, Malamet Exemplar and Gift of the Viper (issue 26). The numbers are provisional: the lead folds these entries into `docs/DECISIONS.md` and renumbers them. The CR text used is the owner's private copy (`COMMANDER_ARENA_CR_FILE`); every rule cited below was read with `pnpm rule`.

## D-1260: Keyword counters (CR 122.1b, 613.1f), and "put a X counter, a Y counter, and a Z counter on ..." (2026-11-13)
- Context: Gift of the Viper puts a +1/+1 counter, a reach counter and a deathtouch counter on a creature. The engine kept counters as free names (`Record<string, number>`) and a counter named "reach" did nothing. CR 122.1b: "A keyword counter on a permanent or on a card in a zone other than the battlefield causes that object to gain that keyword", for flying, first strike, double strike, deathtouch, decayed, exalted, haste, hexproof, indestructible, lifelink, menace, reach, shadow, trample and vigilance (and variants), applied in layer 6 (CR 613.1f). The grammar read one counter kind per instruction, one word long.
- Decision: (1) `derive` adds the keyword of each keyword counter an object has (`rules/keyword-counters.ts`, `KEYWORD_COUNTERS`): the kinds above except decayed, which the engine has no keyword for. A keyword the object already has is not added twice; every counter of exalted is an instance of its own (CR 702.83b: each instance triggers), with the triggered ability the keyword stands for. The counter is named as the keyword is ("reach", "first strike"). (2) Layer 6 orders its effects by timestamp (CR 613.7), and a counter has one as it is put on (CR 613.7c); the engine keeps no timestamp for a counter, so keyword counters apply before everything else in the layer: a later "loses all abilities" effect takes them away, and a counter put on after such an effect began is wrongly removed too (`docs/ROADMAP.md`). (3) The grammar reads `put a X counter, a Y counter, and a Z counter on target creature` (`effect.add-counters-kinds`): two or more counters, each "a" or "an", on one object that is a target, "~" or "it"; one `addCounters` instruction for each counter, in the order written (CR 608.2c), all on the same target (chosen once, CR 115.1). The counter name pattern also reads "first strike" and "double strike". (4) A counter named decayed is dropped, not read as an inert counter (`lower.add-counters` refuses it): honesty about unsupported cards.
- Alternatives: a new effect `addKeywordCounters` (a second way to put a counter, with its own events and replacement hooks; rejected: a keyword counter is a counter, and every rule about counters, such as proliferate, "remove all counters" and counter doubling, applies to it as it is); a derived keyword read where each rule asks for a keyword (the engine reads abilities from `derive` only: one place); counter timestamps (a state change in every place a counter is put on: too large for one card, and recorded as a limitation).
- Consequences: any card that puts a keyword counter (a growing list: Ikoria and later sets) is one lowering away; proliferate, counters removed by costs and the rules for +1/+1 and -1/-1 counters are unchanged. The derive differential digests change only for games that have a keyword counter (none of the precon fingerprints), but `ENGINE_VERSION` moves with D-1261 (state shape).

## D-1261: Base power, and "with power greater than its base power" (CR 208.4b, 613.4b-c) (2026-11-13)
- Context: Kutzil: "Whenever one or more creatures you control each with power greater than its base power deals combat damage to a player, draw a card." CR 208.4b: effects that check a creature's base power "see that creature's characteristics after applying any characteristic-defining abilities and abilities that set power and/or toughness, ignoring any effects and counters that modify power and/or toughness without setting them". The engine computed only the final power.
- Decision: (1) `Derived.basePower` and `baseToughness` are what layer 7b leaves (`derive-layers.ts` `basePtOf`, the effects that set power and toughness, last by timestamp, and the characteristic-defining values), before counters and "+N/+N" effects; null for an object with no power. (2) `ObjectFilter.powerAboveBase: true`: the object's power now is more than its base power; an object with no power matches nothing; read from the object as it is, or from last-known information (`LastKnownInfo.basePower`, optional, kept as an object leaves). Refused where `derive` matches filters (a static ability's subject, a count a static ability reads, an equip quality): it would read the layers it is part of (CR 613.8); it joins `readsCombatOrSource`. (3) The grammar reads " with power greater than its base power" as a noun suffix (`noun.*` phrases, plural also " each with power greater than its base power"), and the batch trigger `trigger.combat-damage-batch` takes the verb "deals" for the "each" wording of the card ("deal" for the group wording). `FilterSubject.basePower` carries it into `matchesFilterWith`.
- Alternatives: a `Condition` on the trigger instead of a filter field (the same test is wanted on targets and on counts: a field of the filter is read everywhere a filter is); comparing with the printed power (wrong for "base power and toughness 1/1" effects and characteristic-defining abilities: CR 208.4b says the final base).
- Consequences: other cards with "greater than its base power" or "power is greater than its base power" read the same field; `ENGINE_VERSION` should move (the last-known information of every object gained a field, so state hashes change) and the derive digests are regenerated.

## D-1262: Tests, the soak style `danithaG6` and the words (2026-11-13)
- Context: AGENTS.md: support is proven per grammar rule and primitive; games-100 expects some question kinds from dedicated styles only.
- Decision: engine scenarios `scenario-xx-danitha-g6-base-power.test.ts` (SYNTHETIC fixtures in `synthetic-danitha-g6.ts`); grammar tests `parser-danitha-g6.test.ts` (real lines, siblings, near misses, the feature the engine lacks) and `convert-grammar-engine-danitha-g6.test.ts` (the real Kutzil and Gift of the Viper from the golden corpus played through `applyAction`); the cards enter `DANITHA_G6_NAMES` and are filtered out of the generic AI pools in `packages/ai/test/helpers.ts`, with the deck style `danithaG6` and `DANITHA_G6_STYLE_PAIRS`, played by `danitha-g6-games.test.ts` (rules checked from the card texts: a keyword counter always shows its keyword, a watcher trigger follows combat damage by a creature above its printed power, the Snare aims at one, a Viper Boon puts its three counters on one creature and untaps it). Web: `trigger-text.ts` says "with power greater than its base power" (`apps/web/test/danitha-g6-text.test.ts`). No new question kind, so no new prompt UI and no browser test.
- Alternatives: none worth listing.
- Consequences: version constants, the golden snapshot and the derive digests are regenerated by the lead (`UPDATE_GOLDEN=1`, `UPDATE_DERIVE_DIGESTS=1`); Kutzil and Gift of the Viper turn from unsupported to supported and nothing else in the golden corpus changes.
