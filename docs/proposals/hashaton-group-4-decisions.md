# Hashaton deck, group 4: decisions (provisional numbers D-1120 to D-1129)

Group 4 of the Hashaton deck (issue 31): Gleaming Overseer ("When this creature enters, amass Zombies 1." and "Zombie tokens you control have hexproof and menace.") and Enter the Avatar State ("Until end of turn, target creature you control becomes an Avatar in addition to its other types and gains flying, first strike, lifelink, and hexproof."). The numbers are provisional: the integrator renumbers them into `docs/DECISIONS.md`.

## D-1120: Amass is an engine effect, `amass { subtype, count }`, run by an instruction (2026-11-13)
- Context: CR 701.47a, "To amass [subtype] N means: If you don't control an Army creature, create a 0/0 black [subtype] Army creature token. Choose an Army creature you control. Put N +1/+1 counters on that creature. If it isn't a [subtype], it becomes a [subtype] in addition to its other types." The engine had no amass. The shape is that of Empower Jace (D-201): make a token if there is none, choose one of the permanents the player controls, put counters on it.
- Decision: `Effect` `amass { subtype: Subtype, count: Amount }` and the instruction `amass { subtype, amount, made?, chosen }` (`rules/amass.ts`). The effect reads N as it begins (CR 608.2h; X is the X of the spell) and queues the instruction. The instruction makes the token when the controller controls no creature with the type Army (as `derive` types it now, any controller's card or token of theirs), chooses an Army with a `choosePermanent` decision of purpose `amass` (asked only with two or more; `min` = `max` = 1), puts N +1/+1 counters on it, and, when it is not the creature type, adds the type with a permanent additive `setTypes` continuous effect (layer 4, `until: 'permanent'`, CR 205.1b, 611.2a, 613.1d). The token is a 0/0 black creature token with the subtypes `[subtype, 'Army']`, named for them (CR 111.4). `amass` is in `SUPPORTED_FEATURES`; `validateCard` wants a creature type and an amount.
- Alternatives: Writing the steps as an `Effect` `sequence` (a conditional `createToken`, a choose, `addCounters`, `setTypes`) was rejected: "choose an Army you control" needs a decision over permanents the effect may have just made, and no existing selector asks it. A `count` that is a plain number (as `empowerJace.amount`) was rejected: "amass X" is a real shape, and `Amount` costs nothing. The old form without a type ("Amass 1") is not read: CR 701.47d says the Oracle text of those cards was errata'd to "amass Zombies N".
- Consequences: Any card with "amass [types] N" is read once the parser rule `effect.amass` (D-1121) is there. Not built: the "amassed" event of cards that trigger on amassing (CR 701.47b: a player amassed even when nothing could be done) and "the Army you amassed" (CR 701.47c); both would read what this instruction chose, and `docs/ROADMAP.md` says so.

## D-1121: The token pipeline and the choice: tokens first, then the question (2026-11-13)
- Context: Empower Jace asks its question before anything is made and throws the token away (it makes the Jace again on the second run), which is fine there because the Jace is made with a flow that does not ask and the choice can only name tokens that existed already. For amass the Army the player chooses may be one the effect made (a replacement that adds a second Army token: "those tokens plus an additional ..."), the token must be made with the replacement questions of its creator (D-221, CR 616.1), and the question has to name objects that exist: the web and the AI read the objects of the decision from the state.
- Decision: The first run of the instruction makes the token with `makeSettled` (the same call `createToken` uses, so the replacement effects of the creation apply and the order question is asked and kept in `ResolutionContext.damageAnswers`), then puts the instruction back at the front of the queue with `made: true`; the next run chooses the Army from a state that has the new tokens and puts the counters on. A question about the order of replacement effects returns with nothing changed (D-221), as for every token. If a replacement makes no Army at all ("that many 1/1 Soldier tokens instead"), the instruction finds no Army, does nothing, and the game goes on (CR 701.47b).
- Alternatives: Making the token and asking in one run, as `empowerJace` does, was rejected (the question names tokens that exist only in the state the run throws away). Putting the counters on the first Army without asking was rejected (CR 701.47a says choose).
- Consequences: The Armies the player chooses among are all on the battlefield when the question is asked, so the web shows them and the AI reads their power. A 0/0 token sits on the battlefield while the question is asked; state-based actions are checked only when a player would receive priority (CR 704.3), after the resolution.

## D-1122: "<Creature type> tokens you control" is a noun phrase and the static grant reads it (2026-11-13)
- Context: "Zombie tokens you control have hexproof and menace." The engine's `grantKeyword` static over `{ token: true, subtypes: ['Zombie'], controller: 'you' }` is run; the noun `noun.token-permanents` read only "creature tokens" and "tokens". "Have hexproof and menace" already lowers to one static `grantKeyword` for each keyword.
- Decision: the noun rule `noun.subtype-token-permanents` (`parser/rules/noun/hashaton-group-4.ts`, listed in `static.permanents`): a creature type, in the singular, then "tokens you control"; the filter is `{ subtypes: [type], token: true, controller: 'you' }`, the group of the permanents that match at any moment (CR 611.3a). The type must be a creature type (CR 205.3m), not a plural ("Zombies tokens"), and no other word is allowed before or after it. The web words the group ("Zombie tokens you control") in `thingsPhrase` for the shapes of tokens it can say: one creature type or the card type creature, one controller, nothing else.
- Alternatives: Extending `noun.token-permanents` with an optional type word was rejected: it leads with "creature" and "tokens" and the type word may be any creature type, so it would have to lead with every word. A new engine filter field was rejected (the filter has `subtypes` and `token`).
- Consequences: Other cards of the shape ("Soldier tokens you control get +1/+1", "Elf tokens you control have haste") read too. A static over "Zombie creature tokens" or two types is not read.

## D-1123: The agents and the web for the question of the Army (2026-11-13)
- Context: A new `choosePermanent` purpose `amass`: the casual agent's last branch is the "sacrifice" chooser, which would pick the weakest permanent; the web words a `choosePermanent` it does not know as a sacrifice.
- Decision: `CasualAgent` (and with it the heuristic agent, which delegates, and the greedy one) answers an `amass` decision with the Army that has the most power, then the most toughness, the first of the list on a tie (`casual-amass.ts`, the shape of the soulbond partner). The random agent chooses among `legal` as for any `choosePermanent`. The web words the question ("Amass: choose an Army you control to put the +1/+1 counters on (Gleaming Overseer)."), gives the chosen Army the badge "Amassed", and words the effect as the cards print it ("Amass Zombies 1", with the plural of the type).
- Alternatives: Choosing the weakest Army (so the strongest is not exposed) or the one that is already the type was rejected: the counters stay on the Army chosen and the type is added either way; a version that weighs removal risk is in `docs/ROADMAP.md`.
- Consequences: No new decision kind: the dialog is the existing permanent picker.

## D-1124: "becomes an Avatar in addition to its other types and gains ..." is one rule that lowers to a sequence (2026-11-13)
- Context: "Until end of turn, target creature you control becomes an Avatar in addition to its other types and gains flying, first strike, lifelink, and hexproof." The engine runs `setTypes` with `additive: true` and one `grantKeyword` for each keyword, each until end of turn on a target; `effect.lead-becomes-target` read the first half and stopped at "and gains", and `effect.gain` reads only a subject followed by "gains".
- Decision: `effect.lead-becomes-target` (`parser/rules/effect/becomes.ts`) reads, after creature types said "in addition to its other types" (the only form the text uses), an optional " and gains " and the keyword list that `effect.gain` reads (`KEYWORD_WORDS`). The clauses share one noun, so the target is chosen once and the `setTypes` and every `grantKeyword` read it (CR 115.1, 611.2c); all of them carry the duration of the lead. Not read: "and gains" after a type that replaces, a card type ("an artifact creature"), a color, a keyword with a parameter or one that cannot be granted (`flash`), another instruction joined to the keyword list, a trailing duration.
- Alternatives: A new rule for the whole sentence was rejected: it would repeat `becoming` and the registry would hold two rules for the same lead. Extending the replacing form ("becomes a Frog and gains flying") was rejected: the replacement of creature types and the keywords of it have no card in the corpus and would be untested.
- Consequences: Any "until end of turn, target <noun> becomes a <creature types> in addition to its other types and gains <keywords>" is read.
