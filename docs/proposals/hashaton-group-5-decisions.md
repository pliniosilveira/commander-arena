# Hashaton deck, group 5: provisional decisions D-1160 to D-1163

Cards: Champion of Wits, Hashaton, Scarab's Fist and Renewed Solidarity (issue 31). The numbers are provisional: the integrator renumbers them into `docs/DECISIONS.md`. Code comments and docs use these numbers. The rulings of the cards could not be fetched (Scryfall is blocked in the cloud sandbox): nothing below rests on one, only on the CR text of the owner's rules repository.

## D-1160: The exceptions of a token copy: power and toughness, colors, creature types, no mana cost (2026-11-13)
- Context: "create a token that's a copy of that card, except it's a 4/4 black Zombie" (Hashaton) and "Eternalize" ("... except it's black, it's 4/4, it has no mana cost, and it's a Zombie in addition to its other types", CR 702.129a). `createToken` of a `copyOf` had two exceptions only: `addSubtypes` and `abilities` (D-230).
- Decision: `copyOf` takes four more optional exceptions, applied as the values are copied (`rules/copy-exceptions.ts`, read by `tokenDefinitionOf`): `setPt { power, toughness }`, `setColors` (empty means colorless), `setCreatureTypes` (the copy is exactly these creature types, instead of the ones it copies; the other subtypes of the original, an artifact type or a land type, stay because they belong to a card type the copy keeps; not with `addSubtypes`) and `noManaCost` (the mana cost is nothing, so the mana value is 0, CR 202.1b). They are part of the copiable values of the token (CR 707.9b), so a copy of the token has them: the definition of the token is built with them. Per CR 707.9d a characteristic-defining ability of the original that defines a characteristic the exception gives a specific value to is not copied: `setPt` drops every `characteristicPt` static ability, `setColors` drops `devoid`, `setCreatureTypes` drops `changeling`; an exception "in addition to its other types" (`addSubtypes`) copies them (a Zombie copy of a changeling card keeps changeling). Validation: the creature types are a non-empty list of creature types and not together with `addSubtypes`, the colors are known and distinct, the numbers are whole, `noManaCost` is `true`. The feature `token:copyExceptions` (`SUPPORTED_FEATURES.tokenKinds`) says the engine runs them; `validateCard` refuses a card that uses one if it were not listed.
- Alternatives: a full `Characteristics` override object on `copyOf` (a wider AST: it would let a card set a loyalty, a mana cost or supertypes that no card needs, and would make the CR 707.9d rule depend on which fields are present); the exceptions as a continuous effect on the token after it enters (they would not be copiable values: CR 707.9b says they are, and Eternalize's token is copied by other effects as a black 4/4 Zombie).
- Consequences: other copy exceptions that give a characteristic a value ("except it's a 1/1 white Spirit") are one more rule input of `token.copy-except`; a copy exception that retains the copier's own values (CR 707.9c, Clone-like replacement effects) is not built. When the original's creature types are replaced and it has a creature-type-defining ability other than changeling (none exists in the corpus), that ability stays. A card of two card types, one of which is a creature (an artifact creature), keeps both: "it's a 4/4 black Zombie" sets creature types only, so the artifact type stays (an unverified reading: the card's rulings could not be read).

## D-1161: "Whenever you discard a creature card": a card filter on the discard trigger (2026-11-13)
- Context: `Trigger.discarded { who }` named whose discard and nothing about the card. Hashaton's trigger says "a creature card" and copies "that card".
- Decision: `discarded` takes `filter?: ObjectFilter`, read against the card where the discard put it (the graveyard, or exile for a card with madness, CR 702.35a, 701.9a), as the card was or, if it has gone, as it last was (CR 113.7a); the filter is matched in the zone of the object (`{ ...filter, zone: subject.zone }`), so it names no zone, controller or owner (the validator refuses them). The triggering object (`triggerSubject`, a permanent reference in the validator since D-206) is the card; a copy of it is made from last-known information if it left before the ability resolved (CR 608.2h). The support check (`ast/supported.ts`, `triggerSubjectFilter`) reads the filter: with none the card could be an Aura card, which a token copy cannot be (CR 303.4f, the same refusal as any copy source), with `types: ['creature']` it cannot. Parser: `trigger.discarded` reads "a/an <card kind> card" and "a non<kind> card" (one kind of the eight card kinds; the article agrees with the next word), the lowering writes the filter only when the words name a kind.
- Alternatives: a new trigger kind for "a creature card" (duplicates the trigger and its occurrence code); a filter on the subject read in the zone the engine chooses (the zone would have to be named, and a madness card is in exile, not in the graveyard).
- Consequences: other "whenever you discard a <kind> card" cards are the same node. Two kinds ("a creature or land card") are not read.

## D-1162: Eternalize is a keyword that expands to an activated ability (2026-11-13)
- Context: Champion of Wits has "Eternalize {5}{U}{U}": "[Cost], Exile this card from your graveyard: Create a token that's a copy of this card, except it's black, it's 4/4, it has no mana cost, and it's a Zombie in addition to its other types. Activate only as a sorcery." (CR 702.129a).
- Decision: a keyword `{ kind: 'eternalize', cost }`, like Encore (D-185) and Unearth (D-124): `rules/derive-keywords.ts` expands it into `{ kind: 'activated', cost: [cost, exileThis], effect: createToken { copyOf this, setColors ['B'], setPt 4/4, noManaCost, addSubtypes ['Zombie'] }, timing: 'sorcery', functionsIn: 'graveyard' }`, with no new effect: the copy is made by `createToken` from the last-known information of the exiled card (the card is exiled as a cost, CR 118.1, and `tokenDefinitionOf` reads `state.objects[id] ?? state.lki[id]`, CR 608.2h, 113.7a). `rules/activate-legality.ts` lists the graveyard keywords (`hasGraveyardAbility`). Validation: the cost is mana only without X, a permanent card, one eternalize ability per face; `validateCard` refuses a card whose face is a land or an Aura (the copy would enter without the questions of a land or the host of an Aura, `copiesThisIssues`). Parser: `keyword.eternalize` (a line of its own, the reminder text dropped, like `keyword.encore`). AI: `CasualAgent` activates it for a creature card of its own in its main phase (`wantsEternalize`, `casual-alt-costs.ts`): the token is a permanent 4/4, so it is worth the mana whenever the option is listed. Web: the chip, the activation label ("Eternalize {5}{U}{U}") and the stack text (the copy with its exceptions).
- Alternatives: a dedicated `eternalize` effect as Encore has (needless: Encore has one because of the attack requirement and the sacrifice; here `createToken` already does the whole thing once it has the exceptions of D-1160).
- Consequences: Embalm and other "token copy from the graveyard" keywords are the same expansion with other exceptions. The token of Champion of Wits enters and its own "When this creature enters" ability triggers with the power the token has: 4 (tested).

## D-1163: Renewed Solidarity: copies of the tokens of the chosen type that entered this turn (2026-11-13)
- Context: "At the beginning of your end step, for each token you control of the chosen type that entered this turn, create a token that's a copy of it." The engine already has `createCopies` (D-213) over an `each` selector, `chosenType`, `enteredThisTurn` and `token`; the grammar read only the Vraska form (with haste and a quoted ability).
- Decision: (1) `copySourceIssues` treats a filter with `chosenType` as one that cannot match an Aura (as it treats `subtypes` that omit Aura): "of the chosen type" names a creature type, which an Aura card or token does not have (CR 205.3d), so a group that has it is accepted; a group with no kind (`{ token: true }` alone) could be a Role token, an Aura, and stays refused. (2) Parser: `effect.copy-each-token` reads "for each token you control[ of the chosen type][ that entered this turn], create a token that's a copy of it", lowered (`lower/hashaton-g5.ts`) to `createCopies` with no ability added. (3) Web: the gist says the group and the copy.
- Alternatives: `types: ['creature']` in the filter (would leave out the tokens of the chosen type that are not creatures: a type chosen from the creature types can be on a tribal non-creature token); allow every token (a Role token is an Aura and the copy would enter without a host).
- Consequences: "for each creature token you control" and the like are other noun shapes, not built. The copies enter after the trigger resolved once, so the new tokens are not copied again (tested).
