# Danitha deck, group 3 (Auras: attachments counted or checked): provisional decisions D-1230 to D-1237

Issue 26, branch `support-danitha`. Cards: Kor Spiritdancer, Sage's Reverie, Winds of Rath, Ethereal Armor, Face of Divinity, Shield of the Oversoul, Shardmage's Rescue, Strong Back. All eight read as supported with no override. The lead folds these entries into `docs/DECISIONS.md` with the next free numbers (the code and the tests say D-1230 to D-1237; the numbers in the code comments are the provisional ones).

The Comprehensive Rules text was not available in this session (`COMMANDER_ARENA_CR_FILE` unset, no `docs/rules/comprehensive-rules.txt`, no network to the private rules repository). The rule numbers cited are the ones the code and the docs of the repository already use (CR 303.4 Aura, 301.5 Equipment, 701.3 Attach, 611.3a, 613.8, 400.7, 601.2c, 601.2f, 602.2b, 702.6a, 118.7a, 701.19c, 702.11b hexproof); the exact subrule of the definition of "enchanted" (a permanent with an Aura attached to it) was not looked up and is unverified. Scryfall rulings were not fetched (blocked); none is relied on.

## D-1230: Attachments as filter fields: `attachedTo`, `enchanted`, `hostOfSource` (CR 303.4, 301.5, 701.3)

- Context: six of the eight cards count or test what is attached to a permanent: "+2/+2 for each Aura attached to it", "for each Aura you control that's attached to a creature", "Aura and Equipment attached to it", "creatures that aren't enchanted", "another Aura is attached to enchanted creature". The engine had `GameObject.attachedTo` and `StaticSubject` `attached`, but no way to count or filter by an attachment.
- Decision: `ObjectFilter` gets three fields, read from the object table (the attachment is no characteristic of any layer, so a static ability may count it): `attachedTo` (`{ kind: 'source' }` the permanent with the ability, `{ kind: 'host' }` the permanent the source is attached to, `{ kind: 'matching', filter }` any permanent a plain filter describes: types, subtypes, colors, supertypes, controller, no layer 6 or 7 reading), `enchanted` (`true`: at least one Aura is attached; `false`: none; an Equipment is no Aura) and `hostOfSource: true` ("enchanted creature" as the object another filter describes). `matchesFilterWith` reads them with a new `FilterContext.describeOther` (the caller says how another object is described: `derive` for the rules that read the game, `typeViewOf`, layers 1, 4 and 5 only, for `derive` itself, so counting cannot loop, CR 613.8). Without it the fields fail closed. `validateCard` checks them (battlefield only; the host filter of `matching` may not name anything but the plain fields; the static checks allow them in counts and conditions), `SUPPORTED_FEATURES` lists `selector:attachedTo`, `selector:enchanted`, `selector:hostOfSource`.
- Alternatives: a new `Amount` kind "attachments of" (does not give "Aura you control that's attached to a creature" or the filter of Winds of Rath); a card-name or subtype special case (forbidden).
- Consequences: any "for each Aura/Equipment attached to it", "creatures that aren't enchanted", "enchanted creature" filter of a spell or cost reduction now has an engine form. Limits: a host of `matching` is described by types only in the parser (a color or a controller of the host is engine-ready but not read).

## D-1231: Static conditions "this entered this turn" and a count of objects (CR 400.7, 611.3a, 613.8)

- Context: Shardmage's Rescue: "As long as this Aura entered this turn, enchanted creature has hexproof."; Face of Divinity: "As long as another Aura is attached to enchanted creature, it has first strike and lifelink." A static ability could read the life total, a turn count, the controller's permanents by `controlsAtLeast` (always "you control") and `thisMatches`, but not whether the source entered this turn nor a count of any kind of object.
- Decision: a new `Condition` `thisEnteredThisTurn` (the source is the object that entered the battlefield this turn, read from `turnLog.entered`: a permanent that left and came back is a new object, CR 400.7; allowed in a static ability in any layer, `PLAIN_CONDITIONS`, and in a `conditional` effect or an intervening "if"). The existing `amountIs` is also read by a static ability when its amount is a `countOf` (`staticConditionHolds`, `countForSource`: layers 1, 4 and 5; `validateCard` refuses any other amount there: a greatest, a total or a devotion read power). `SUPPORTED_FEATURES` lists `thisEnteredThisTurn`.
- Alternatives: `thisMatches` with `enteredThisTurn` (the filter field is refused in a static ability: it reads the turn log through a context `derive` does not build); `controlsAtLeast` for the Auras (forces "you control").
- Consequences: "as long as ~ entered this turn", "as long as there are N or more X attached/on the battlefield" read in a static ability. The condition holds as soon as the Aura enters, so the hexproof is there before any player could respond to the Aura spell's resolution; it ends with the turn (the turn log is reset), CR 611.3a.

## D-1232: A cost reduction that reads what the spell targets (CR 601.2c, 601.2f)

- Context: Strong Back: "Aura spells you cast that target enchanted creature cost {3} less to cast." D-207 did this for the spell's own reduction (`spellTargets`); a permanent's reduction (`costReduction` with a filter) matched only the spell's own characteristics.
- Decision: the spell filter of a `costReduction` may carry `targetsObject` (the existing filter field of D-206) at its top level, read when the total cost is determined (the targets are chosen first, CR 601.2c before 601.2f); `checkCostReduction` allows it (its inner filter describes a permanent on the battlefield). The question "may this spell be cast at all?" (`canCast`, `canPayRequest`) assumes the most favourable target (`SelectContext.spellTargetsMayHold`, as `spellTargets` does, D-207) as long as no target is chosen. Once the targets are chosen the cost is the real one.
- Because a player who could pay only with the reduction must not be offered a target that does not give it, the first mandatory target slot offers, in that case, only the targets after which the total cost is payable (`rules/target-payable.ts`, `payableSpellTargets`, `targetChoiceSpecs` has a new `payable` list). When the cost is payable without the reduction nothing is restricted.
- Alternatives: leaving the player to choose and be stuck at the payment (the AI of the soak did get stuck in the first runs of the design); cancelling the cast after the choice (a started cast is never cancelled by the AI, `cancel` can loop).
- Consequences / limits (`docs/ROADMAP.md`): only the first mandatory slot is restricted (an Aura has one); a spell with two target slots where the second one could be the cheap target is offered fewer choices than the rules allow.

## D-1233: A cost reduction of Equip abilities that reads what they target: `abilityCostReduction` (CR 601.2f, 602.2b, 702.6a, 118.7a)

- Context: Strong Back: "Equip abilities you activate that target enchanted creature cost {3} less to activate." The engine had the ability's own reductions (`costReducedIf`, `costReducedBy`) but no static ability of another permanent that reduces the cost of activated abilities.
- Decision (engine): a new static `{ kind: 'abilityCostReduction', abilities: 'equip', targeting: ObjectFilter, amount }` (positive generic mana, only the generic part of the first mana cost, never below zero, adds up with other reductions). The ability the Equip keyword expands to is marked `equip: true` (`equipAbility` in `derive-keywords.ts`; `validateCard` refuses the field in card data). The reduction is determined when the targets are chosen (`answerTargets` calls `reduceForChosenTargets`, which puts the reduced ability on the stack and into the activation, CR 602.2b), by the permanents the activating player controls whose `targeting` filter matches a target (the permanent with the ability is the source, so `hostOfSource` is the permanent it is attached to; `equipReductionFor` in `activate-adjust.ts`, the sources are indexed by `derive-statics.ts`). `activationRefusal` offers the Equip when some legal target makes its reduced cost payable, and the targets decision offers only the targets after which it is payable (D-1232, `payableEquipTargets`). `SUPPORTED_FEATURES` lists `static:abilityCostReduction`.
- Alternatives: a `costReducedBy` on every Equip (the reduction belongs to the Aura, not to the Equipment); reducing the ability's cost when it is put on the stack, before the targets (CR 602.2b: targets first).
- Consequences: an Aura of an opponent on your creature does nothing for you ("Equip abilities you activate"); the reduction applies to every Equip ability of the player, including a granted one.

## D-1234: Parser: the nouns and counts of attachments

- Context: the grammar read neither "Aura attached to it" nor "Aura you control that's attached to a creature" after "for each", nor "creatures that aren't enchanted", and the statement "gets +1/+1 for each enchantment you control and has first strike" stopped at "and has".
- Decision: `ATTACHMENT_SUFFIX` (`rules/noun/danitha-g3.ts`) after a counted singular phrase of `amount.for-each`: " attached to it" (IR `attachedTo` `it`) and " that's attached to a creature" (`type`), which also names the objects, so a phrase with no controller needs no "on the battlefield". A static ability binds "it" (`bindAttachedIt`, `lower/danitha-g3.ts`): of `~` it is the source ("This creature gets +2/+2 for each Aura attached to it"), of "enchanted creature" the permanent the source is attached to; for any other subject "it" stays unbound and the count is not lowered (never guessed). `noun.all-enchanted`: "all creatures [you control] that aren't enchanted" (also "that are enchanted"), an operand of every permanent verb. `static.pt-count` reads " and has/have KEYWORD" after the count (one `modifyPt` and one `grantKeyword` for each keyword).
- Alternatives: lowering "it" always as the source (wrong for Strong Back); a new engine amount.
- Consequences: other cards with "for each Aura attached to it", "destroy all creatures that aren't enchanted", "gets +N/+N for each X you control and has K" read.

## D-1235: Parser: conditions about the host and the turn, and "it"

- Decision: `condition.host-is-color` ("enchanted/equipped creature is green", one color; the engine's `objectMatches` of the permanent the source is attached to, so Shield of the Oversoul's green and white lines are exact for a creature of both colors and follow a color change), `condition.other-attached-to-host` ("another Aura is attached to enchanted creature", "another Equipment is attached to equipped creature"; `amountIs` of a `countOf` with `other` and `attachedTo` `host`, at least 1) and `condition.this-entered-this-turn` ("~ entered this turn", "~ entered the battlefield this turn"). The conditional static statements read "enchanted creature ..." statements as units (`static.attached` words) and, after a condition about the host only, "it ..." as that same permanent (`hostPronounUnit`: after "As long as enchanted creature is green, it gets +1/+1 and has indestructible"; "it" after any other condition is not read). The lowering needs the face to be an Aura for "enchanted" and an Equipment for "equipped".
- Alternatives: one rule for any "enchanted creature is ..." (a creature type, a keyword or a power would read layer 6 or 7).
- Consequences: Face of Divinity and Shield of the Oversoul give one static ability per keyword and per bonus, each with the condition.

## D-1236: Parser: the two reductions of Strong Back

- Decision: `static.equip-cost-reduction` ("Equip abilities you activate that target enchanted creature cost {N} less to activate.") lowers to `abilityCostReduction` for an Aura only; `static.spells-cost-reduction` also reads " you cast that target enchanted creature cost {N} less to cast" (`IrFilter.targetsHost`, lowered to `targetsObject: { hostOfSource: true }`, for an Aura only). Generic mana only.
- Consequences: other Auras with these words read; "that target equipped creature" and the plural/opponent forms are not read.

## D-1237: Web wording, AI and tests

- Web: `attachment-text.ts` words the filters ("Aura attached to it", "Aura you control that's attached to a creature", "creatures that aren't enchanted", "other Aura and Equipment attached to it"), the conditions ("another Aura is attached to the permanent this is attached to", "this permanent entered this turn") and the two reductions ("Equip abilities you activate that target enchanted creature cost {3} less to activate", "Aura spells you cast that target enchanted creature cost {3} less to cast"); a host or a filter it cannot say is left out, never guessed (`apps/web/test/danitha-g3-text.test.ts`).
- AI: no new decision kind. `CasualAgent` casts "Destroy all creatures that aren't enchanted" only when the opponent loses more creatures than it does, counting the creatures with no Aura attached on both sides (`isEnchanted`, `casual-priority.ts`); the HeuristicAgent follows through the same `worthCasting`. The restriction of the targets (D-1232, D-1233) keeps every AI choice completable. The SYNTHETIC cards are kept out of the generic soak pools (`DANITHA_G3_NAMES`) and have the deck style `danithaG3` with the pairs `DANITHA_G3_STYLE_PAIRS` (`packages/ai/test/danitha-g3-games.test.ts`).
- Tests: engine `scenario-xx-danitha-g3-attachments.test.ts` (SYNTHETIC cards of `synthetic-danitha-g3.ts`), cards `parser-danitha-g3.test.ts`, `convert-grammar-engine-danitha-g3.test.ts` (the real text of the eight cards through the grammar, compared with the SYNTHETIC cards and played), web `danitha-g3-text.test.ts`, AI `casual-danitha-g3.test.ts` and `danitha-g3-games.test.ts`. Mutation checks (on the engine files, restored after each): `attachedTo` `source`, `host` and `hostOfSource` made too loose, `enchanted` counting an Equipment, `thisEnteredThisTurn` always true, an opponent's Aura reducing the Equip, the optimistic target of the cast removed, the payable-target restriction removed for spells and for Equip: each is caught by a test.
- Corpus tests moved: none needed (no test named a line that is now read). The `static.pt-count` reject "~ gets +1/+1 for each artifact you control and has flying." moved to the examples (now read), and the rejects were rewritten around the forms still not read.
