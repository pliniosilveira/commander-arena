# Niv-Mizzet deck, group 2b-a: decisions to enter in `docs/DECISIONS.md`

Provisional numbers D-940 to D-944; the integrator renumbers them (the code, the tests and the docs of this group say D-940 to D-944). Cards: Living Conundrum and Niv-Mizzet, Visionary (issue 25).

## D-940: The plain condition `cardsInLibrary` (2026-11-12)

- Context: Living Conundrum's third line is "As long as there are no cards in your library, this creature has base power and toughness 10/10 and has flying and vigilance." and its second line needs the same test as the `while` of a replacement. The engine had `cardsInGraveyard` (D-229) for the graveyard of the controller and nothing for the library.
- Decision: a `Condition` `cardsInLibrary { compare }` (`NumberComparison`: `atMost` 0 is "no cards", `atMost` N-1 is "fewer than N"). It reads the number of cards in the library of the controller (`cardsInLibraryHolds`, `rules/condition-reads.ts`) and no characteristic, so it is one of the plain conditions (CR 613.8, 611.3a): a static ability of layer 4, 5, 6 or 7b may have it (`PLAIN_CONDITIONS`, `plainConditionHolds`, `static-conditions.ts`), and `derive` reads it each time it works out the permanent. The parser reads "there are no cards in your library", "your library has no cards in it" and "fewer than N" forms (`condition.cards-in-library`), registered with the conditions of a static ability.
- Alternatives: an `amountIs` of a `countOf` the library: rejected, because `amountIs` reads the game through the layers and is not allowed in a layer 4/7b static ability, which is exactly where the card needs it; a special static for the card: rejected, no card-name code.
- Consequences: any "as long as" static ability or replacement `while` that depends on the size of the controller's library reads right; "an opponent's library" and a kind of card in it are not read (`docs/ROADMAP.md`).

## D-941: The replacement `skipDraw` of a draw (2026-11-12)

- Context: "If you would draw a card while your library has no cards in it, skip that draw instead." CR 614.11 and 121.6a: an effect that replaces a draw applies even when the library has no cards, so the player attempted no draw and does not lose to an empty library (CR 121.4, 704.5b). `drawCard` set `drewFromEmptyLibrary` before any effect could replace the draw.
- Decision: a `Replacement` `skipDraw { while?: Condition }` of a permanent on the battlefield. Every draw goes through `drawCard` (an effect through `runDraw`, and the draw step of `flow.ts`), which now asks `drawSkippedBy` (`rules/draw-skip.ts`) first, before it looks at the library. The oldest permanent of the controller whose abilities (read through `derive`, so "loses all abilities" turns it off) have a `skipDraw` whose `while` holds (a plain condition read for the controller, `plainConditionHolds`) skips the draw: the state is unchanged, the event is `drawSkipped { seat, source }`, and no `cardDrawn` or `drewFromEmptyLibrary` follows. Each draw of a sequence is replaced on its own (CR 614.11a, 121.6b), so the cards of "draw three" before the library emptied are drawn and the rest skipped. `validateCard` allows only a plain `while` (`checkPlainCondition`). Parser: `replacement.skip-draw`; web words and a log line "<permanent> skips your draw."
- Alternatives: a flag on the player ("skips draws"): rejected, it would not follow the permanent leaving or losing its abilities and could not carry a condition; checking the library before the replacement: rejected, it is the bug the rule describes; a new decision for several replacements (CR 616.1): not needed, all applicable replacements give the same result (the draw is skipped), so no order is asked.
- Consequences: no new question for any player, so the agents need no new answer. A replacement that does something else instead of the draw (CR 614.11b) is not built (`docs/ROADMAP.md`). The `drawSkipped` event is listed in the event tables (`test/face-down-hidden.test.ts`) and in the log (`apps/web/src/game/describe.ts`).

## D-942: The trigger `noncombatDamageDealt` (2026-11-12)

- Context: Niv-Mizzet, Visionary: "Whenever a source you control deals noncombat damage to an opponent, you draw that many cards." The triggers on damage were `dealsCombatDamage` (a permanent that deals combat damage), `dealtDamage` (a permanent dealt damage) and `combatDamageBatch`; none names any object as the source or noncombat damage.
- Decision: a `Trigger` `noncombatDamageDealt { by: 'you' | 'any', to: 'opponent' | 'player' }`. It has one occurrence for each `damageDealt` event (CR 120.2b: damage as an effect of a spell or ability, by any object) to a player that is not combat damage and has an amount above 0 (CR 120.8: 0 damage is not dealt; CR 603.2g: prevented damage triggers nothing), with `triggerDamage` the amount that source dealt to that player ("that much", and "that many" as the first instruction of the body), `triggerPlayer` the player damaged and `occ.seat` the controller of the source, read as it is or as it last was (CR 113.7a), because a spell on the stack, an ability or a permanent that has left can be the source. One source damaging several players, or several sources, are several `damageDealt` events and trigger once each (CR 603.2c). The source is not a permanent with a filter, so the trigger has no subject. Parser: `trigger.noncombat-damage`, four combinations of "a source [you control] deals noncombat damage to [an opponent | a player]"; the lowering of `lifeGainThatMany` is generalized to `eventAmountThatMany` (the life gained or the damage dealt, the first instruction only).
- Alternatives: reuse `dealtDamage` with the recipient a player: rejected, it names a permanent as the one dealt damage; a batch trigger ("one or more sources"): the text is not batched, and CR 603.2c gives one trigger for each occurrence; a source filter of permanents: rejected, a spell is a source and not a permanent.
- Consequences: noncombat damage by any object to a player can trigger abilities. The ruling that one spell damaging several opponents triggers the ability once for each opponent follows CR 603.2c and the events of `damage.ts`; the Scryfall rulings could not be fetched in this session, so this is UNVERIFIED against them. The scenario DSL has two seats, so the several-players case is by the structure of the events, not a scenario.

## D-943: Parser registration and the diagnostics of other cards (2026-11-12)

- Context: the three new rules start with broad words ("if", "a", "there", "your"), and the golden corpus records the closest rule of each unparsed line, so a new rule that reports its failures can move the "stopped at" of other cards.
- Decision: the three rules are `quietly` (their failures are left out of the diagnostics; their matches are recorded as usual), as the Angels rules are (D-150). The golden corpus then changes for exactly the two cards of this group (Living Conundrum and Niv-Mizzet, Visionary: unsupported to supported); no other card's status, diagnostics or AST changed (read from the golden test). `condition.cards-in-library` is added to the conditions a static ability reads (`rules/static/conditional.ts`).
- Alternatives: leaving the rules loud: rejected, the "closest rule" of unrelated cards would change in the golden snapshot for no reason.
- Consequences: `golden.expected.json` is regenerated by the integrator (`UPDATE_GOLDEN=1`); the build's version constants are bumped there too.

## D-944: The `nivDraw` deck style of the AI soak tests (2026-11-12)

- Context: the new SYNTHETIC cards (a creature that skips draws, creatures that draw when damage is dealt) would join the generic card pools of the AI tests and change the seeded games of every older test, and the draw replacement changes when a player loses to an empty library.
- Decision: the names are kept out of every other pool (`NIV_DRAW_NAMES`, `packages/ai/test/helpers.ts`) and used by a deck style of their own, `nivDraw`, with `packages/ai/test/niv-draw-games.test.ts` playing whole games between random and casual agents (every game finishes, no fallback, no rejected action, consistent state, an exact replay), restating from the events that a skipped draw names a skipping permanent of the player's on the battlefield and that a player with a skipping permanent in play never draws from an empty library. No decision kind was added, so no agent needed a new answer.
- Alternatives: leaving the cards in the generic pools: rejected, it shifts every seeded game; no AI test: rejected, the replacement changes a game-ending rule.
- Consequences: `pnpm test:soak` (100 games) checks that every card of the style is cast and that an empty library is drawn from at least once. The pool of the engine's derive differential test takes every synthetic card with a static condition, so `packages/engine/test/derive-digest.expected.json` was recorded again (`UPDATE_DERIVE_DIGESTS=1`) for `SYNTHETIC Hollow Warden`; with the new fixtures left out, the old fingerprints match, so the new engine code changes no earlier game. Another group that adds a synthetic card with a static condition re-records the same file, so the integrator regenerates it once after merging all groups.
