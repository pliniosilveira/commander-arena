# M3 progress report: First playable

Date: 2026-10-21. Branch `m3-first-playable`.

## What is done

- **Worker architecture (D-044).** `GameHost` owns the real `GameState`, applies the human's action and lets the AI answer until the human is asked something, with the A28 watchdog (an answer far past its budget is replaced by the safe fallback and counted). Comlink exposes it from a module Worker; tests drive the same class in process. The page receives snapshots only: the human's view, the steps and events since the last snapshot, log lines and the fallback count.
- **Auto-pass (A18, D-018, D-045).** `shouldStop(view, settings)` is a pure, tested function; the zustand store's autopilot sends `pass` and `payAuto` as ordinary actions, with a "Passing…" chip that seizes priority. Default stops: your two main phases and every real decision; nothing on the opponent's turn unless an opponent's object is on the stack and you hold a castable instant. Per-step stops (every turn or this turn), Full Control, manual mana.
- **Board and cards (A19, D-019, D-046).** Both players' strips with life, counts, command zone, commander tax and damage; three rows per battlefield with shrinking, token grouping with a count badge, and horizontal scroll; tapped rotation, attacking and blocking marks, keyword chips, counters, damage, summoning sickness, an unsupported badge; a fanned hand where playable cards glow and the hovered card lifts; a fixed preview panel with a 150 ms hover delay, right-click pin and Esc unpin; zone viewers. Cards are CSS frames behind one seam where images can replace them.
- **Every decision UI built so far:** priority, mulligan, bottom after mulligan, discard, targets, manual payment, commander zone, attackers (with planeswalker and battle targets), blockers (menace aware), damage division with the lethal-first hint. Keyboard: Space or Enter for the primary action, Esc to unpin, close and cancel, F for Full Control.
- **Panels and screens:** turn tracker with stop toggles, stack panel with SVG arrows to targets, filterable game log with optional CR references, settings, menu with a deck picker for both seats and a seed, the honesty summary (A28), and a game-over dialog with replay download.
- **Test decks (D-047).** Three 100-card fixture-only decks.
- **Deploy (D-023, D-049).** GitHub Pages is not free for private repositories, so the site deploys to Cloudflare Pages through `wrangler.jsonc`; the Pages workflow is manual. Playwright (1.56.1, D-046) smoke tests run in CI.
- **Spikes (D-048).** The owner ran the A20 spikes on 2026-10-21; findings in `docs/spikes/RESULTS.md`: bulk data is gzipped JSON Lines and double-faced cards match only by front-face name.

## Test status

`pnpm typecheck`, `pnpm lint`, `pnpm test` and `pnpm build` pass on the branch head. The browser tests: `pnpm --filter @commander-arena/web exec playwright install chromium` (or set `CHROMIUM_PATH`), then `pnpm e2e`. They play from the menu through a mulligan, a land, four more turns clicking only the primary button, and a concession. The game-level tests (`apps/web/test/host.test.ts`, `store.test.ts`) play whole games through the store with a scripted human and assert that the player is never asked anything on the opponent's turn except a response with an instant or a block.

M3 done-when (SPEC 15): a full 1v1 game with the test cards against `RandomLegalAgent`, with stack panel, log and every decision UI needed so far: yes. Checkpoint: stop and report how to run it.

## How to run it

`pnpm install`, `pnpm dev`, open the printed address, press Start game. Or use the deployed site once Cloudflare Pages is connected (D-049). Skip the menu with `?autostart=white-knights,swamp-forest&seed=7`; deck ids are `white-knights`, `swamp-forest`, `instants`.

## Known gaps

See "M3 known limitations" in `docs/ROADMAP.md`. The main ones: no card images, no animation, the opponent plays randomly, and some dialogs (manual payment, damage division, colour chooser, commander zone) were verified by tests and markup only, not by a live browser game.
